# 設計

## LLM に任せること / プログラムに任せること

| LLM (考える) | 通常のプログラム (確実にやる) |
|---|---|
| 次に何をするか (行動ツールと引数を選ぶ) | 移動・採掘・クラフト・建築・戦闘の実際の操作 (`src/agent/actions.js`) |
| 短期目標・長期目標の設定、約束 | 状況の要約 (体力・時間・持ち物・敵・周囲のブロック) (`perception.js`) |
| 誰が・どんな態度で返事するか (進行役)、会話・返事・黙るかどうか | 誰が返事をするかの交通整理、無限会話の防止 (`conversation.js`) |
| 相手の発言をどう受け取ったか (喧嘩・謝罪・仲裁…) | 関係の数値の増減と、その根拠となる出来事の記録 (`relationships.js`) |
| 日記・印象の書き直し・成長・教訓 | 日付の変化の検知、日記の保存、記憶の整理のタイミング |
| 仲間の死への反応、墓を建てるか | 死亡地点・死因の記録、教訓、慎重さの上昇、全員への通知 |
| — | **安全管理**: 反射行動と、LLMの行動案の審査 (`safety.js`) |

## 1回の判断の流れ

1. **知覚**: ゲームの状態を短い日本語にする
2. **反射** (毎秒・LLMなし): 溶岩/火 → 退避、体力低下+敵 → 逃走、クリーパー接近 → 逃走、空腹 → 食事。実行中の行動は中断
3. **意思決定** (LLM): 人格 + 状況 + 関連する記憶 + 教訓 + 関係 + 共有の歴史 + 計画 + 最近の会話 → JSON で `{thought, say, action, goal}`
4. **安全審査**: 体力が低いときの戦闘、勝てないボス、装備に見合わない遠出、夜の素手探索、プレイヤーへの攻撃などを却下・修正。却下理由は次の判断で LLM に伝わる
5. **実行**: 行動ツールが Mineflayer で操作し、結果を日本語で返す
6. **記録**: 成功/失敗を記憶に保存。近くで一緒に作業した仲間とは「一緒に〇〇した」が関係に加わる (同じ2人は1日1回まで)

## 記憶

- `memories` テーブル: 人ごと (`agent` 列) に完全に分離。種類は event / chat / success / failure / lesson / goal / reflection / summary / death
- 想起: 「重要度 + 新しさ + 今の状況との文字の重なり (日本語は2文字ずつ比較)」で上位を選ぶ。埋め込みモデル不要で 6GB VRAM を圧迫しない
- 整理: 有効な記憶が `memory.maxActive` (400) を超えると、日記のあとに古くて重要度の低い記憶をLLMで要約して1件にまとめる。教訓・死・要約は残す
- 共有記憶 (`shared_events`): 家の完成、死亡、お墓、発見、新しい目標、計画の提案 など全員の歴史
- 会話の記憶: その人が**実際に聞こえた**発言だけを覚える (聞こえる距離 32m。名指しされた場合は遠くても聞こえる)

## 人間関係

- 片方向 (ハル→リン と リン→ハル は別)。`affinity` (好き嫌い) と `trust` (信頼) は -100〜100
- プロンプトには数値ではなく「好き・信頼」などの言葉、関係ラベル (親友/ライバル…)、言葉の印象、**最近の実際の出来事**を渡す
- 変化のきっかけ: 返事のときに LLM が相手の発言を「good_talk / insulted / quarrel / apology / reconciled / mediated …」と判定、プレゼント、約束を守った/破った (日記で判定)、一緒に作業、計画への参加
- 日記を書くときに LLM が印象とラベルを書き直す → 数値だけでなく経験に基づいた関係になる

## 会話

- AIの発言はゲーム内チャットに表示しつつ、プロセス内のイベントバスで確実に届ける (日本語・長文の取りこぼし防止)
- 名指しされた人は必ず返事を検討。名指しなしの発言には1人だけが反応 (社交性が高い人ほど反応しやすい)
- 同じ2人の往復が `max_bot_exchanges` 回に達したらクールダウン。AI全体の発言数にも1分あたりの上限
- 人間がログインすると、その人と一番親しいAIが「◯時間ぶり」を踏まえて出迎える

## 死亡

1. 死因 (サーバーの死亡メッセージ)・場所・日を `deaths` に記録
2. 本人: 死の記憶 (重要度9) と教訓 (例: 溶岩→「足元を確認」) を保存。慎重さ +1 → 逃げる体力・戦闘禁止の体力が上がり、探索距離が短くなる
3. 仲間全員: 関係に応じた重要度で死を記憶し、LLM で反応 (発言・気持ち・目標の変化・墓を提案するか)
4. 誰かが墓を提案すると計画 `#n ◯◯のお墓` が登録され、各自の判断材料に出る → `build_grave` (墓石・看板の墓碑・花) → 墓は保護区域になる → `visit_grave` で墓参り
5. `death.permanent=true` なら、その人は永久に退場。家は保護区域として残り、誰も壊さない

## 9人に増やすとき (STEP 6) の負荷対策

- `llm.max_pending` 以上の思考が待っていたら新しい判断を始めない (キュー詰まり防止)
- 会話返事を優先度0で割り込ませる
- `decide_interval_ms` を人数に応じて伸ばす、遠くにいる人の判断頻度を下げる (今後)
- 同じ人のプロンプト前半 (人格・行動一覧) を固定して、Ollama のプロンプトキャッシュが効きやすい形にしている
